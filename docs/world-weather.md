# 世界地图天气

晴天、阴天、雨天、薄雾沿用原有循环与 8 秒渐变。雪域章节的降水阶段使用飘雪，雨声强度为零。

雨滴分三个景深批次绘制，落到接触点后转为溅滴和扁平涟漪。地形接触点来自当前方块高度的投影；水面使用较宽的涟漪。建筑与树木是二维美术贴图，接触点按真实 Alpha 轮廓近似屋顶与树冠，不使用整个贴图矩形。被造景遮住的地形落点会被剔除。相机、视差与窗口尺寸变化后，接触点随之更新。

## 性能预算

- 天气最多每秒绘制 24 次，低质量档进一步降频。固定粒子池容量 900；桌面按画面面积取 200–900，窄屏最多 320。持续较高的 CPU 绘制耗时会降低粒子量，稳定恢复后逐步提高。
- 云块几何只在尺寸、光照档位或质量档位变化时栅格化；平时每帧移动、缩放 7 张缓存图。1440×900 时缓存约 2.47 MB，不再单独创建云层 WebGL 上下文。
- 30 份造景轮廓在地图进入时以 64×64 解析一次。动画期间不读取图片像素；接触点仅随视角变化限频更新，最多每秒 10 次，静止时复用。
- 地形几何沿用原缓存。指针视差使用合成层位移，避免每次指针运动都重绘山体。天气动画独立运行，不驱动地形重绘。
- 后台、关闭地图、减少动态效果均停止动画回调。关闭时清理天气画布、云缓存、轮廓缓存与事件监听。

## 验证

`tests/world-map-weather.test.cjs` 覆盖周期连续性、粒子边界、接触终止、水花、落点缓存、雪天、手机预算、自适应质量、云缓存、后台暂停及释放，通过 Python 天气测试包装进入项目 CI。

浏览器回归使用正常开始游戏流程进入地图，检查山体/地面/造景接触、相机移动、指针移动不增加地形帧数、静止天气不重建接触点、手机尺寸、减少动态效果和退出清理。时间快进测试同时调整动画与性能时钟，避免制造错误的帧率结论。浏览器使用软件图形后端，实际设备帧率仍取决于显卡和整个页面的合成开销，不能将 CPU 绘制耗时等同于完整帧耗时。
